# Agent Note: 浏览器持有的 Dock 浮签垂直位置

Status: implemented

[English](2026-09-05-draggable-dock-rail.md) | 中文

## 问题

DSH 的轮次导航位于视口中部附近的右侧边缘。居中的 BranchMark 浮签会遮挡这些控件，而固定偏移无法适应所有窗口尺寸或相邻插件。

## 决策

收起后的浮签默认位于垂直中线上方 120px，并支持单指针沿右侧边缘上下拖动。Pointer Capture 持有每次手势；松手时提交受限的相对位置，取消、视口缩放或组件卸载时释放持有关系。六像素移动阈值区分点击与拖动，拖动产生的兼容点击不会展开 Dock。方向键、Home 和 End 提供键盘定位，Enter 和 Space 保留按钮激活行为。

读取时可缺省的 `railPosition` 字段属于既有 `dsh-branchmark.ui.v1` 浏览器偏好，不属于 Host 的 Clip 存储。null 或缺失值使用默认位置；保存值表示可用垂直行程中的比例，因此缩放视口后仍保持可见，无需重写保存的坐标。该偏好不包含 Clip 正文、Session 引用或模型输入。

## 考虑过的替代方案

**只移动固定浮签。** 这可以分开默认控件，但其他插件占据该位置时，用户无法自行调整。

**允许不受限的二维拖动。** 这会允许浮签遮挡消息正文，并增加沿边缘交互不需要的水平状态。

**在 Host 中保存绝对像素。** 各浏览器的尺寸不同。Host 持久化会把本地布局选择与共享持久数据耦合，而且仍需进行视口修正。

## 后果

浮签保持为覆盖层，不调整 DSH 布局。用户可以主动把它放到其他控件附近；默认偏移之外的避让由用户手动完成。浏览器拒绝存储时，内存内交互仍可使用。集合排序决策独立保留，因为它负责持久 Clip 顺序，而不是浮签几何位置。

## 验证

所属组件测试覆盖鼠标与触摸手势、点击抑制、键盘移动、受限缩放、旧偏好与非法偏好、存储拒绝、取消以及监听器和捕获释放。发布检查验证同号的 DSH 0.1.2-rc.1 peer 依赖图和自包含公开 Bundle。真实 Web Profile 检查负责视觉遮挡和浏览器事件投递证据。
