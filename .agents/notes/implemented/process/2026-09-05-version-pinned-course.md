# Agent Note: Version-pinned course and layered verification

Status: implemented

English | [中文](2026-09-05-version-pinned-course.zh.md)

## Problem

A plugin course can combine released APIs, moving upstream source, local artifacts, and npm tags into one apparent target. Readers then reproduce nonexistent commands or mistake unit tests for browser, provider, or data-migration evidence.

## Decision

One version-baseline reference owns the release target and registry snapshot. Mainline lessons use that target; migration exercises name an independent source snapshot. A separate Session-identity reference explains why handle migration alone cannot repair persisted Clip anchors.

The route inserts the Dock interaction lesson after selection and references, retains existing numbered URLs, and places labs at prerequisite checkpoints. Course pages retain their established Chinese tutorial format; they are not a projection of upstream package READMEs.

The source-only course verifier uses maintained Markdown libraries to check the baseline, package scripts, generated entry names, heading links, and reachability. It runs through the existing documentation check in CI. Pure invalid fixtures exercise rejection rules without executing document commands or starting applications.

## Alternatives considered

**Replace version strings only.** This leaves mixed APIs, obsolete generated filenames, and missing interaction lessons. Current API facts and migration exercises need separate teaching paths.

**Renumber every chapter.** This breaks links without improving prerequisites. An inserted 6A lesson and explicit route provide the order while preserving filenames.

**Execute every Markdown command automatically.** Courses contain environment setup, foreground servers, and model-costing exercises. The verifier inspects a constrained command vocabulary; experiment owners run environment-dependent operations with scoped evidence.

## Consequences

One baseline and one verification matrix reduce duplicated version and coverage claims. Documentation-only development dependencies provide Markdown and GitHub heading parsing; public plugin dependencies and runtime behavior do not change. The checker does not prove API semantics, browser layout, model behavior, or user-data compatibility across versions.

The Client ownership, collection ordering, and draggable-rail notes retain independent decisions and are not superseded by this course-process record. Runtime limitations remain explicit limitations, not silent feature changes in a documentation task.

## Verification

Positive and invalid fixtures validate the course checker. Document links, fixed source targets, generation, package checks, and an isolated exact-version CLI install verify the written entry paths. Real provider and browser scenarios have explicit manual experiment owners; the course does not publish packages or promote dist-tags.
