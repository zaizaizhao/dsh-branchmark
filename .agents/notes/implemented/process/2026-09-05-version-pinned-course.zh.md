# Agent Note: 固定版本课程与分层验证

Status: implemented

[English](2026-09-05-version-pinned-course.md) | 中文

## 问题

插件课程可能把已发布 API、移动上游源码、本地产物和 npm 标签混成一个目标。读者因而复现不存在的命令，或把单元测试误当成浏览器、provider 和数据迁移证据。

## 决策

版本基线参考统一维护 release 目标和注册表快照。主线使用该目标，迁移实验固定独立源码快照。Session 身份参考单独解释为什么只迁移 handle 不能修复持久 Clip 锚点。

路线在选区和引用后插入 Dock 交互课，保留既有编号 URL，并把实验放到先修检查点。课程保留既有中文教学格式，不作为上游 package README 的投影。

只读课程检查使用维护中的 Markdown 库，检查基线、package script、生成入口名、标题链接和页面可达性。它通过既有文档检查进入 CI。纯错误 fixture 验证拒绝规则，不执行文档命令或启动应用。

## 考虑过的替代方案

**只替换版本字符串。** 这会留下混合 API、失效生成文件名和缺失交互课。当前 API 事实与迁移实验需要不同教学路径。

**重排所有章节编号。** 这会破坏链接，却不改善先修关系。插入 6A 课和显式路线可以提供顺序，同时保留文件名。

**自动执行所有 Markdown 命令。** 课程包含环境配置、前台服务和有模型成本的实验。检查器只检查受限命令形式，实验执行者在明确范围内运行环境相关操作并记录证据。

## 后果

一个基线和一份验证矩阵减少重复版本和覆盖声明。仅用于文档开发的依赖提供 Markdown 与 GitHub 标题解析，公开插件依赖和运行行为不变。检查器不能证明 API 语义、浏览器布局、模型行为或跨版本用户数据兼容。

Client 所有权、集合排序和可拖动浮签记录保留各自独立决策，不被本课程流程记录取代。运行时限制仍作为限制说明，不在文档任务中静默改变功能。

## 验证

正向和错误 fixture 验证课程检查器。文档链接、固定源码目标、生成、包检查和隔离精确版本 CLI 安装验证书面入口。真实 provider 与浏览器场景有明确人工实验所有者；课程不发布包或提升 dist-tag。
