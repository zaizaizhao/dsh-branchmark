# 枝签 · BranchMark 产品需求

## 目标

用户在一个持续推进的 DSH 会话中发现值得保留的回答时，可以摘录原文并生成枝签，在旁边探索而不必向当前 Session 追加问题、破坏主线的上下文连续性。枝签既是可整理的本地知识对象，也是创建临时 Side Chat 或普通衍生 Session 的显式输入。

## 范围与术语

- **枝签（BranchMark）**：由不可修改的摘录正文、不可修改的来源锚点、可修改备注和多标签组成的分支起点。
- **Clip**：枝签摘录数据在源码和持久层中的类型名；不是另一个面向用户的产品对象。
- **会话枝签**：只属于 owner Session；仅在该会话的“本会话”视图中可见。
- **项目枝签**：属于 Workspace；只在该项目的“项目”视图中跨会话可见，不混入“本会话”视图。
- **Side Chat**：Host 内存中的临时、只读、多标签对话，不是普通 DSH Session。
- **完整分叉**：以一枚主要枝签的来源消息事件序号为锚点，调用 DSH 原生 Fork，边界是该消息所在轮次的完整 `turn/end`。
- **仅携带枝签**：创建干净的新 Session，不继承父会话历史；Host 把用户显式选择的枝签写成只读 `recall` 上下文，Composer 保持空白。

## 纯插件可行性与边界

目标版本 DSH 的 API Session Controller 在 `ctx.sessions` 上公开 `fork` 和 `create`，所以本插件不要求 DSH 新增 Fork API，也不修改 DSH 源码。完整分叉的 `sessionId` 是主要枝签的来源 Session；即使来源锚点位于父会话中间，分叉结果也会继承该父会话从开头到来源消息所在完整轮次为止的历史，而不是只复制摘录正文。

DSH 把 Fork 的历史前缀记录为新 Session 的 seed，并在新 Session 中按普通历史显示。插件只增加继承横幅、来源跳转和边界分隔线，不需要把一批伪造消息写入新 Session，也不需要宿主提供额外的“隐藏历史渲染”接口。若未来目标 DSH 版本不再导出 Fork/create 或不再投影 seed，纯插件无法等价重建这一能力，并且必须明确报错，不能退化为复制文本后伪称完整分叉。

Side Chat 是不同机制：较早历史摘要、最近原始消息、完整枝签和备注只组成 Host 内存中的模型上下文，不进入普通 Session，也不要求前端重建或隐藏这些历史。关闭 Side Chat 或 Host 退出后该上下文立即消失。

## 已冻结的产品规则

1. 枝签不按 Worktree 隔离，只绑定 Workspace 与 owner Session。
2. “本会话”视图只展示当前会话自己的会话枝签；项目枝签只在“项目”视图展示。
3. 新枝签默认属于本会话，可一键提升为项目枝签；提升同一记录，不复制。
4. 单消息连续选区形成一枚枝签；跨消息选区按消息拆成多枚枝签。
5. 枝签的摘录正文和来源不可编辑；备注与标签可编辑。备注默认随枝签进入新上下文，但可逐枚取消。
6. 项目枝签只在界面中全局可见，不自动进入任何模型请求。
7. 项目枝签视图提供全文搜索、多标签交集筛选和卡片/列表切换，不提供文件夹。
8. 枝签没有标题；摘录正文是卡片主内容。
9. Side Chat 永远临时且只使用只读工具；允许多个标签页。收起或隐藏共享 Dock 不销毁 Side Chat，关闭标签立即中止并销毁。
10. Side Chat 不建立普通 Session，只能使用固定的最小只读工具集合。
11. 创建普通 Session 时，跨来源枝签必须显式选择主要来源；同来源默认使用事件序号最新的枝签。其他枝签始终作为附件。
12. “创建并打开”跳转到新 Session，枝签作为只读回忆上下文写入日志且 Composer 保持空白；“创建并发送”在来源页面收集问题，创建后通过 Session `prompt()` 在后台直接运行。
13. 完整分叉不允许静默降级。来源消息、事件序号、完成轮次或持久化历史不可用时，必须提示用户显式选择仅枝签。
14. 新 Session 显示继承横幅和来源入口；枝签卡片列出并可打开其衍生 Session，双方保留双向关联。
15. 删除进入回收站；永久删除枝签不影响衍生 Session 与已经冻结的使用快照。
16. 数据只存 DSH 本地；导入/导出留作后续版本。
17. Side Chat 上下文由“AI 摘要较早历史＋安全用户消息边界后的最近原始消息＋完整枝签”组成；摘要输入是较早历史的纯文本 transcript，在首次发送时生成，默认跟随用户当时选定的 Side Chat 模型，也可配置专用摘要模型。摘要失败时使用最近原始消息与完整枝签继续回答，并展示 provider 错误。
18. Dock 默认最小化为右侧中部把手；展开时作为浮层避开 Session Header 与 Composer，不改变 DSH 主会话列或页面布局尺寸。Dock 可调整宽度、再次最小化或完全隐藏，不使用遮罩。
19. 本会话、项目、会话关系和 Side Chat 在同一个 Dock 中切换；会话关系树只属于插件 UI，不修改原生侧边栏。
20. 枝签卡片可把枝签引用到当前主输入框，但绝不自动发送。Composer 使用 DSH 原生 Reference Chip，只展示短预览；完整原文与启用的备注在提交事务中序列化，不展示内部 XML 标签。DSH draft mirror 在重载时恢复 `@branchmark:<id>` 持久化投影；Client 从当前可见集合解析 id 并重新插入原生 Chip。无法解析、已回收或不可见的 token 必须保持普通可见文字，不能伪装成携带模型上下文的有效引用。
21. Side Chat 的助手回答与思考过程按 Markdown 渲染，只读工具活动使用可折叠行展示，交互与主对话保持相同的阅读层级。
22. Side Chat 默认沿用来源消息当时的 provider、model 与 reasoning effort；用户可在临时会话内独立切换 DSH 已公布的模型和思考强度，不修改来源 Session 的模型选择。
23. 已完成消息的有效选区显示紧凑的“摘录到会话 / 摘录到项目 / Ask in side / 引用到输入框”操作条；前两个动作显式选择保存范围，后两个动作先保存为本会话枝签。长选区可跨 Markdown 块，跨消息仍拆成多枚枝签，所有动作均显式触发且不会自动发送主会话消息。
24. 多选枝签后不展开常驻批量按钮条，只显示“处理 N 枚枝签”命令胶囊。命令面板提供引用到输入框、Side Chat、新会话、置顶或取消置顶、追加标签和移入回收站；批量引用保持用户勾选顺序，窄宽度下命令只显示图标但保留可访问名称。
25. 枝签卡片使用统一的折叠阅读高度；长正文可在原卡片内展开，也可进入居中的聚焦阅读视图。置顶和手动顺序按当前会话集合或项目集合持久化；拖拽只在未搜索、未筛选且置顶状态相同的完整集合内启用，跨组移动必须显式切换置顶状态。

## 核心流程

### 生成枝签

1. 用户选择一条或多条消息中的文本。
2. 插件从 DSH Chat Node 映射到 `MessageId`、事件序号、轮次与 canonical 文本范围。
3. Host 重新读取持久化 Session，核对来源身份和 `excerpt === canonical.slice(range)`。
4. 用户选择保存到本会话或项目；Host 持久化一枚包含不可变来源和正文的枝签。

### Side Chat

1. 用户选择一枚或多枚枝签，并选择主要来源。
2. Host 读取主要来源所在完整轮次以前的 Session 前缀和当时的 request config。
3. 首次发送时，较早消息转换为单条纯文本 transcript 后通过 AI 摘要，最近消息从安全的用户消息边界开始原样保留，枝签与启用的备注完整加入隐藏上下文；因此发送前的模型切换也控制默认摘要模型，工具调用与结果不会被切分到上下文两侧。
4. 用户在临时抽屉中提问；Host 直接调用 `ctx.llm.stream`，必要时执行固定只读工具。
5. 用户可在回答开始前切换临时会话自己的模型；Host 用 `resolveCallConfig` 校验，来源 Session 不变。
6. 关闭标签后 Abort 当前调用并删除内存状态，不保留普通 Session 或 Side Chat 日志。

### 普通衍生 Session

1. **完整分叉**：`ctx.sessions.fork({ sessionId: sourceSessionId, atSeq: sourceEventSeq })`。DSH Host 选择第一个 `seq >= atSeq` 的 `turn/end`，并包含下一轮开始前的独立尾随事件。
2. **仅携带枝签**：`ctx.sessions.create({ workspaceId })`，不设置父会话或 seed。
3. Host 校验新 Session header：完整分叉的 `parentSession` 与精确 `seedLength` 必须匹配来源边界；仅枝签不得有 parent/seed。
4. Host 写入一条衍生关系和全部 Clip 使用快照，并向新 Session 追加一条可折叠、可恢复的 `recall` 上下文消息。
5. 创建模式打开空白 Composer；发送模式只通过 Session `prompt()` 提交用户问题，已记录的枝签上下文由 DSH 模型历史一并读取。

## 验收标准

- [x] 会话私有与项目全局读取在 Host Remote 层隔离，包括回收站。
- [x] 来源与正文由 Host 对持久化 Session 二次验证。
- [x] 原文不可编辑，备注和标签可编辑。
- [x] 跨消息选区拆分。
- [x] 搜索、多标签、卡片/列表、批量元数据操作。
- [x] 原生完整分叉与无 parent/seed 的仅枝签会话。
- [x] 创建并打开不发送；创建并发送后台运行。
- [x] 衍生关系、双向跳转、使用快照与删除独立性。
- [x] 多标签临时 Side Chat、最小化、取消、立即销毁。
- [x] 自动摘要、最近原文、完整 Clip、专用摘要模型配置。
- [x] 固定只读工具集合和项目目录 containment。
- [x] Side Chat 回答可继续生成枝签。
- [x] 不改变宿主布局尺寸的浮动 Dock、上下安全区、右侧中部最小化把手与完全隐藏。
- [x] 本会话、项目、关系树和多标签 Side Chat 共用 Dock。
- [x] 会话关系树从 `parentId` 投影，并以稳定分支色区分。
- [x] Side Chat 渲染思考过程和 Markdown 回答，使用主对话式迷你输入区。
- [x] Side Chat 可独立切换 DSH 模型与思考强度，并展示只读工具活动。
- [x] 衍生 Session 的枝签上下文进入日志而不占用可编辑 Composer。
- [x] 卡片可插入 DSH 原生枝签引用，Composer 不显示完整摘录且不自动发送。
- [x] 页面重载后，DSH draft mirror 中可解析的 BranchMark 持久化 token 自动恢复成原生 Chip，其他草稿文本保持不变；无法解析的 token 保持可见且不会伪装成有效引用。
- [x] 紧凑选区操作条支持分别摘录到会话或项目、Side Chat 和主 Composer 引用；跨 Markdown 块选区与多引用逐条移除保持稳定。
- [x] 多选命令胶囊提供六个批量入口，批量 Composer 引用保持勾选顺序并且不自动发送。
- [x] 长正文支持固定卡片、卡片内展开和聚焦阅读；置顶与同组拖拽顺序按会话或项目集合持久化。
- [x] 搜索或标签筛选期间禁用持久化拖拽，Host 拒绝不完整集合和跨置顶组的排序请求。
- [x] 亮色与深色模式全部使用 DSH 语义主题 token。
- [ ] 导入/导出（明确的未来范围）。

## 实机验收说明

重新打包后的自包含 tarball 已安装到真实 DSH Web profile。浏览器验收覆盖内嵌安全区 Dock、最小化把手、340px Dock 的批量命令图标化、固定卡片、卡片内展开、聚焦阅读、置顶分组、按勾选顺序生成原生 Composer 引用、本会话与项目枝签隔离、内嵌新会话流程、`parentId` 关系树、临时 Side Chat 创建、模型目录与思考强度菜单，以及亮色/深色主题。验收不发送模型请求；完整集合排序与拒绝路径、Host 生命周期、模型路由切换、上下文组装和工具活动投影由自动化测试覆盖。

本轮浏览器验收不以 fixture 或 mock 伪装模型回答。配置有效 provider 凭证后的流式输出、真实摘要、工具调用和回答质量仍需单独做 API e2e。

## 非目标

- 修改 DSH 核心源码或要求新增原生 Fork API。
- 用文件夹组织枝签。
- 将项目枝签自动注入所有会话。
- 允许 Side Chat 写文件、运行命令、修改 Session 或请求审批升级权限。
- 删除枝签时修改历史 Session。
